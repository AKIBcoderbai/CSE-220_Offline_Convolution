CH 01

The six identities that generate every question

All three past onlines — and almost any variation they can invent — are one of these identities wearing a costume. If you can name which identity a spec is using within the first minute, the coding is mechanical.

I1 · Impulse ↔ step:  h[n] = s[n] − s[n−1]   and   s[n] = Σk≤n h[k]
Why: δ[n] = u[n] − u[n−1], and u[n] = Σ δ. LTI systems inherit both relations. (Online A)
I2 · Difference trick:  y = x ∗ h = Δx ∗ s   where Δx[n] = x[n] − x[n−1]
Differencing one side of a convolution and integrating the other cancels out. (Online A)
I3 · Series (cascade) = convolve the h's:  x → h₁ → h₂  ⇒  h_eq = h₁ ∗ h₂
Associativity: (x ∗ h₁) ∗ h₂ = x ∗ (h₁ ∗ h₂). Order never matters. (Online B)
I4 · Parallel = add the h's:  x → h₁, x → h₂, outputs summed  ⇒  h_eq = h₁ + h₂
Distributivity: x ∗ h₁ + x ∗ h₂ = x ∗ (h₁ + h₂). A minus branch just means h₁ − h₂. (Online B)
I5 · Linearity over inputs:  (x₁ + x₂ + …) ∗ h = x₁∗h + x₂∗h + …
Convolve each input separately, add the outputs — or add inputs first. Same answer. (Online C)
I6 · Impulse identities:  x ∗ δ[n] = x   and   x ∗ δ[n−k] = x[n−k] (a pure shift)
Convolving with a shifted impulse just relocates the signal. The instant sanity check for any system you build.

Also always true and worth stating in comments for easy marks: commutativity (x ∗ h = h ∗ x — you proved it via polynomials) and the output range rule (starts add, ends add, length = len(x) + len(h) − 1).

CH 02

The recipe toolbox — memorize these

Six short helpers cover every past and predicted question. Write them at the top of your exam file in the first three minutes, before you even read the spec twice.

# R1 — subtraction (your API only has add/multiply)
def subtract(a, b):
    return a.add(b.multiply(-1.0))

# R2 — first difference:  Δx[n] = x[n] - x[n-1]
def first_difference(x):
    return subtract(x, x.shift(1))

# R3 — convolve two SIGNALS (e.g. two impulse responses):
#      wrap one as a system, feed the other as input
def convolve(a, b):
    return LTISystem(a).output(b)

# R4 — running sum / accumulator: s[n] = sum of h[k] for k <= n
#      (step response of h; 'extra' extends the flat tail)
def running_sum(h, extra=5):
    s = DiscreteSignal(h.start_time, h.end_time + extra)
    total = 0.0
    for n in s.times():
        total += h.get_value_at_time(n)
        s.set_value_at_time(n, total)
    return s

# R5 — time reversal: y[n] = x[-n]
def reverse(x):
    r = DiscreteSignal(-x.end_time, -x.start_time)
    r.x_n = x.x_n[::-1].copy()
    return r

# R6 — the verification + report block (the last mark, every time)
def verify(y1, y2, label="methods"):
    d = max_absolute_difference(y1, y2)
    print(f"Max |difference| between {label}: {d:.12g}")
    return d
Why R3 works LTISystem(a).output(b) computes b ∗ a, and convolution is commutative, so it equals a ∗ b. This one-liner is how you build h_combined for any block diagram without writing a new convolution.

The standard plotting block

fig, axes = plt.subplots(3, 1, figsize=(10, 8), constrained_layout=True)
x.plot("Input x[n]", ax=axes[0])
h.plot("Impulse response h[n]", ax=axes[1])
y.plot("Output y[n]", ax=axes[2])
fig.savefig("result.png", dpi=150)
plt.close(fig)

Change the 3 and the list of signals as needed. With the Agg backend already set in your main.py, always savefig — never rely on plt.show().

The standard file-reading block

def read_signal_file(path):
    with open(path, "r", encoding="utf-8") as f:
        lines = [ln.strip() for ln in f
                 if ln.strip() and not ln.strip().startswith("#")]
    start, end = map(int, lines[0].split())
    values = list(map(float, lines[1].split()))
    assert len(values) == end - start + 1, "sample count != range length"
    sig = DiscreteSignal(start, end)
    sig.x_n = np.array(values, dtype=float)
    return sig

This is your existing parse_signal logic packaged for the exam's "one file, one signal" format (Online A used exactly this: line 1 = nstart nend, line 2 = samples). The assert catches the classic silent-misalignment bug.

CH 03

Online A — step response (solved & dissected)

The spec: given s[n] (file) and x[n] (file), recover h[n] = s[n] − s[n−1], compute Δx[n], produce ys = Δx ∗ s using only the step response, verify against yh = x ∗ h.

Identities used: I1 + I2. The whole exam is four lines of real logic once the recipes exist:

s = read_signal_file("step_response.txt")
x = read_signal_file("input_signal.txt")

h  = first_difference(s)          # Task 2: h[n] = s[n] - s[n-1]
dx = first_difference(x)          # Task 3: Δx[n]

ys = LTISystem(s).output(dx)      # Task 4: y = Δx * s  (only the step resp.)
yh = LTISystem(h).output(x)       # Task 5: y = x * h   (verification)

verify(ys, yh, "step-response method vs impulse method")

Then one plotting block for s, h, Δx, ys, yh (a 5-row subplot) and you're done.

Why the marks were distributed the way they were

  • h[n] carried 3 marks because the trap is s[−1]: naïvely looping and indexing s[n-1] at the left edge crashes or misreads. Your get_value_at_time returning 0 outside the range handles it silently — shift + add never touches a raw index. Say so in a comment; examiners reward students who show they saw the edge case.
  • Range subtlety: s.shift(1) ends one sample later than s, so h's range is [s.start, s.end+1] — the extra final sample is h[end+1] = 0 − s[end], which is correct (the step response is flat afterward only if s has settled; if the file's s is truncated mid-rise, that last negative sample is a real artifact worth mentioning).
  • ys and yh have different ranges but identical values — your max_absolute_difference already compares over the combined range, treating missing samples as 0. That's why verification "just works."
Deeper: prove y = Δx ∗ s in two lines (in case they ask "why")

Δx ∗ s = (x − x·shift 1) ∗ s = x ∗ s − x ∗ s·shift 1 = x ∗ (s − s[n−1]) = x ∗ h.

Each step is linearity or time-invariance of convolution. Differencing can hop between the two factors freely — that's the exam's entire theoretical content.

CH 04

Online B — block diagrams (solved & dissected)

The spec: x feeds h₁ and h₂ in parallel; their sum feeds h₃; output is y. Compute y by (a) applying the three systems separately, (b) building one equivalent h_combined, then verify both agree.

Identities used: I3 + I4. h_combined = (h₁ + h₂) ∗ h₃.

# Path (a): walk the diagram literally
y1 = LTISystem(h1).output(x)
y2 = LTISystem(h2).output(x)
y_mid = y1.add(y2)                       # the + junction
y_a  = LTISystem(h3).output(y_mid)       # through h3

# Path (b): collapse the diagram first
h_combined = convolve(h1.add(h2), h3)    # (h1 + h2) * h3   [R3!]
y_b = LTISystem(h_combined).output(x)

verify(y_a, y_b, "separate systems vs h_combined")

The general algorithm for ANY diagram they draw

  1. Series chain → convolve the impulse responses (convolve(hA, hB)), in any order.
  2. Parallel branches into a + junction → add the impulse responses. A branch entering with a minus sign → subtract.
  3. Repeat inward-out: collapse the innermost structure first, treat the result as a single block, keep going until one h remains.

Any feedback-free diagram, no matter how baroque, falls to those three moves. Practice reading a diagram and writing its h_combined as an expression before touching code: the exam diagram above is literally the expression (h1 + h2) * h3.

Range check that catches wiring mistakes h_combined's range must be (h₁∧h₂ start... math: min start of the sum) + h₃'s start → for signals all starting at 0: start 0, end = max(end₁, end₂) + end₃. If your h_combined is longer or shorter than that, you convolved the wrong pair. Ten-second check, saves five minutes.
CH 05

Online C — Supersignal (solved & dissected)

The spec: a Supersignal class holds several DiscreteSignals; add LTISystem.output_super returning the output for the superposition.

Identity used: I5 — pure linearity. Two equally valid one-liners; implement one, verify with the other:

class Supersignal:
    def __init__(self, signals):
        self.signals = list(signals)

# In LTISystem — method 1: convolve each, then add the outputs
def output_super(self, supersignal):
    total = None
    for sig in supersignal.signals:
        y = self.output(sig)
        total = y if total is None else total.add(y)
    return total

# Method 2 (verification): add the inputs first, convolve once
def output_super_v2(self, supersignal):
    combined = supersignal.signals[0]
    for sig in supersignal.signals[1:]:
        combined = combined.add(sig)
    return self.output(combined)

Linearity says both produce the same signal — that comparison IS your verification section, and it's also the conceptual point being examined. One sentence in a comment ("equal by linearity of LTI systems") signals you know why, not just how.

Edge case worth one defensive line An empty signals list: method 1 returns None, method 2 crashes on index [0]. Guard with if not supersignal.signals: raise ValueError("Supersignal is empty"). Cheap robustness marks.
CH 06

Predicted questions — eight variations, all solved

The pattern across A, B, C: take one identity, dress it in a scenario, demand two computation paths plus a verification. Here is that pattern applied in every remaining direction. Attempt each before opening the solution.

PREDICTED V1

Reverse of Online A: given h[n], use the step response

You're given h[n] and x[n]. (1) Construct the step response s[n] using only Signal operations. (2) Compute y via y = Δx ∗ s. (3) Verify against x ∗ h.

Solution
s  = running_sum(h, extra=len(x))   # R4: s[n] = Σ h[k], k ≤ n
dx = first_difference(x)
ys = LTISystem(s).output(dx)
yh = LTISystem(h).output(x)
verify(ys, yh)

The one decision: how far to extend s's flat tail. It must cover every output index where Δx ∗ s can be nonzero, so extending by at least len(x) is safe. If s is cut too short, ys's late samples silently drop to 0 and verification fails — the intended trap.

PREDICTED V2

Pure cascade: x → h₁ → h₂ → h₃ → y

Compute y by chaining the three systems, then via a single equivalent system, then verify. Bonus: show the chaining order doesn't matter.

Solution
y_a = LTISystem(h3).output(LTISystem(h2).output(LTISystem(h1).output(x)))

h_eq = convolve(convolve(h1, h2), h3)     # associativity (I3)
y_b = LTISystem(h_eq).output(x)
verify(y_a, y_b)

# bonus: any order of collapsing gives the same h_eq
h_alt = convolve(h1, convolve(h2, h3))
print(max_absolute_difference(h_eq, h_alt))   # 0
PREDICTED V3

Diagram with a minus branch

x feeds h₁ and h₂; the junction computes (branch1 − branch2); the result feeds h₃. Find h_combined, compute both ways, verify.

Solution
h_combined = convolve(subtract(h1, h2), h3)   # (h1 − h2) * h3

y_a = LTISystem(h3).output(
        subtract(LTISystem(h1).output(x), LTISystem(h2).output(x)))
y_b = LTISystem(h_combined).output(x)
verify(y_a, y_b)

Nothing new — a minus junction is just I4 with a −1 coefficient. Note that if h₁ = h₂ the whole system annihilates every input (h_combined ≡ 0); a cute follow-up question they could ask.

PREDICTED V4

Parallel-of-series: (h₁→h₂) in parallel with (h₃→h₄)

Two cascades run side by side and their outputs are summed. Collapse to one system, verify both paths.

Solution
h_combined = convolve(h1, h2).add(convolve(h3, h4))   # h1*h2 + h3*h4

y_a = LTISystem(h2).output(LTISystem(h1).output(x)).add(
      LTISystem(h4).output(LTISystem(h3).output(x)))
y_b = LTISystem(h_combined).output(x)
verify(y_a, y_b)

Inner structures first (each series → one h), then the outer parallel (add). That's the CH 04 algorithm verbatim — the diagram just nests one level deeper than Online B did.

PREDICTED V5

Echo system built from impulses

Build the echo system h[n] = δ[n] + 0.6·δ[n−4] using only unit_impulse. Show (a) convolving x with δ[n−4] equals x.shift(4), and (b) the echo output equals x + 0.6·x.shift(4).

Solution
h = DiscreteSignal.unit_impulse(0).add(
        DiscreteSignal.unit_impulse(4).multiply(0.6))

# (a) shifted-impulse identity (I6)
y_shift = LTISystem(DiscreteSignal.unit_impulse(4)).output(x)
verify(y_shift, x.shift(4), "conv with δ[n-4] vs shift(4)")

# (b) echo two ways
y_conv   = LTISystem(h).output(x)
y_direct = x.add(x.shift(4).multiply(0.6))
verify(y_conv, y_direct, "echo via conv vs via shift+add")

This is the "do you actually understand what convolution with an impulse does" question. It's also the fastest possible sanity test for any system you write: feed unit_impulse(0) in, and the output must equal h itself.

PREDICTED V6

Correlation via convolution (the flip returns!)

Add a method computing the cross-correlation r[n] = Σk x[k]·h[k−n] using your existing convolution code plus a reverse operation.

Solution
def correlate(x, h):
    return LTISystem(reverse(h)).output(x)   # x * h[-n]  (R5 + R3)

Correlation is convolution without the flip — so pre-flipping h and then convolving (which flips it back) yields correlation. You personally hit this exact confusion in Practice Problem 1, when your hand computation produced [1, 1, 0, 4] (the correlation) instead of [2, −1, 3, 2] (the convolution). Now the bug you made by accident becomes a feature you implement on purpose. If this appears, it's worth easy marks to you specifically.

PREDICTED V7

Weighted Supersignal

Extend Online C: Supersignal now also stores coefficients, representing a·x₁ + b·x₂ + …. Implement output_super honoring the weights, verify both linearity directions.

Solution
class Supersignal:
    def __init__(self, signals, coefficients=None):
        self.signals = list(signals)
        self.coefficients = (list(coefficients) if coefficients
                             else [1.0] * len(self.signals))

def output_super(self, ss):
    total = None
    for c, sig in zip(ss.coefficients, ss.signals):
        y = self.output(sig).multiply(c)      # c·(x*h) = (c·x)*h
        total = y if total is None else total.add(y)
    return total

Whether you scale the input before convolving or the output after is irrelevant — scalar multiplication commutes with convolution. Verify by computing it the other way (scale inputs, add, convolve once).

PREDICTED V8

Inverse systems: difference then accumulate

Feed x through the first-difference system (h_d: 1, −1), then through the accumulator. Show you recover x exactly. Explain via impulse responses.

Solution
h_d  = impulse_first_difference()             # from your main.py
y1   = LTISystem(h_d).output(x)               # Δx
y2   = running_sum(y1, extra=0)               # accumulate it back
verify(y2, x, "difference→accumulate vs original")

Why: the cascade's equivalent impulse response is h_d ∗ u[n] — and accumulating (1, −1) gives (1, 0, 0, …) = δ[n]. A system whose combined h is δ[n] is the identity (I6). Two systems whose convolution is δ are called inverse systems — if the term appears in the spec, this is what it means.

Hand-computation drills (they sometimes ask you to pre-verify on paper)

  • h = (1, 1) at n=0,1 → s = (1, 2, 2, 2, …). Check: difference s back → (1, 1, 0, 0…). ✓
  • x = (1, 2) ∗ h = (1, 1) → y = (1, 3, 2). Ranges: 0..1 conv 0..1 → 0..2. ✓
  • (h₁+h₂)∗h₃ with h₁=δ[n], h₂=δ[n−1], h₃=(1,1): (1,1)∗(1,1) = (1,2,1). ✓
  • Echo δ[n]+0.5δ[n−2] applied to x=(2,4): y = (2, 4, 1, 2). ✓
CH 07

Traps — including two live bugs in your uploaded code

Bug 1 · unit_step has an integer dtype In signal_lti.py: temp.x_n = np.ones_like(temp.n). Since temp.n is an int array, x_n becomes int — any later set_value_at_time(t, 0.5) silently truncates to 0. Fix tonight:

temp.x_n = np.ones(len(temp.n), dtype=float)
Bug 2 · INF = 10000 makes unit_step explosive unit_step creates a 10001-sample signal. Convolve that with anything and you loop ~10⁸ times in pure Python — your exam machine will hang. If a question needs u[n], don't use unit_step; build a finite step over exactly the range you need, or use running_sum on δ. At minimum, drop INF to ~100 for the exam.
Trap · shift direction shift(1) produces x[n−1] (delay/right). Getting this backwards flips h = s − s[n−1] into s[n+1] − s, which "looks plausible" in plots and silently fails verification. When in doubt, test on unit_impulse(0): shift(1) must move the spike to n=1.
Trap · float comparison Never if y1 == y2 or np.array_equal. Two mathematically equal paths differ by ~1e-16 after different operation orders. Always max_absolute_difference < 1e-9.
Trap · sample count vs range make_signal(0, 4, [1,2,3]) — 5-slot range, 3 values — currently succeeds and corrupts silently (length-3 array under a length-5 index range). Keep the assert from the CH 02 reading block.
Trap · set_value_at_time out of range raises When building a result manually, allocate the full output range first (starts add, ends add). If you see IndexError mid-exam, your target signal's range is too small — don't "fix" it by catching the exception.
Trap · numpy.convolve is banned Online A said it explicitly. Assume it's banned always — everything must route through your LTISystem. (After the exam, comparing against np.convolve(x.x_n, h.x_n) is a great private test.)
Trap · reusing mutable signals Your shift/multiply/add correctly return copies — but direct sig.x_n = other.x_n (no .copy()) aliases the arrays, so editing one edits both. You did it right inside the class; keep doing .copy() in any new helper (note reverse in R5 does).

Sixty-second pre-submission checklist

  • Ran the file top to bottom once, fresh, no errors
  • Max absolute difference printed and is < 1e-9
  • Every plot the spec asked for is savefig'd (count them against the marks table)
  • Output ranges match the (starts add, ends add) rule
  • Fed unit_impulse(0) through the final system → output equals h_combined
  • File renamed to your student ID exactly as the spec demands
